## 3. 1.0.0历史版本满容量实测

本节及benchmark.json保留为改版前原始性能记录，不能解释为1.5.0重新执行的结果。当前版本完成下列功能、布局、退出、公式／PDF、外观和即时编辑回归；新模式、大语料、背景与玻璃材质在其他硬件上的性能仍需实测。

环境：Windows 11（10.0.26200）、Intel Core i9-14900HX、32逻辑处理器、16 GiB内存；Node测试宿主24.12.0。成品运行时实测为Electron44.9.1及Node24.22.0。未将本机结果外推为4核／8 GB规定设备的结果。

合成资料库实际包含10,000篇有效笔记、314,572,800字节正文（300 MiB）、2,000个标签、每篇20个标签、100,000条有效引用。内容为可重复生成的课程测试文本，文本重复率较高；恢复与压缩结果不代表任意真实语料的最差情况。

### 3.1 查询和保存

每类查询100次，所有首次请求、后续同版本缓存命中和慢样本均保留，按第95个值取P95。软件缓存最近8个查询页；以下P95不能解释为100个不同冷查询的性能。原始数组及最大值可在benchmark.json检查。

| 指标 | 本次实测 | 目标口径 | 判定 |
|---|---|---|---|
| 标题搜索P95 | 约0.70 ms；最大约24.23 ms | P95≤1秒 | 本语料与查询集合通过 |
| 标签搜索P95 | 约0.61 ms；最大约28.59 ms | P95≤1秒 | 本语料与查询集合通过 |
| 正文搜索P95 | 约0.68 ms；最大约817.52 ms | P95≤2秒 | 本语料与查询集合通过 |
| 综合搜索P95 | 约0.65 ms；最大约707.33 ms | P95≤2秒 | 本语料与查询集合通过 |
| 普通保存100次 | P95约499.30 ms；最大约576.74 ms | 每次≤2秒；不含输入防抖 | 通过 |
| 对应增量索引100次 | P95约34.17 ms；最大约35.43 ms | 每次提交后≤2秒 | 通过 |

查询集合包括标题片段、标签、重复正文、1码点无结果查询及不存在的内容。此处按脚本实际集合记录，不宣称覆盖所有2码点、高命中、冷启动、组合筛选和缓存条件；进一步正式基准仍应扩充。

### 3.2 重建、备份和恢复

静态重建实际执行5次，每次均从主数据重新构建搜索与引用；本轮最大约46.51秒，小于60秒目标。完整备份约19.80秒。正常完整恢复（包括保护备份）首次约114.82秒，内存优化后复测约58秒；复测精确值以原始JSON为准，均小于180秒目标。恢复后再次核对业务字段、版本、索引笔记数及有效关系数。

benchmark.json的initial_index_ms约1.12秒是**复用已存在健康索引时的后台初始化及同步**，不等同于完整Electron主界面启动计时，也不是本轮首次全量构建耗时。首次全量索引在先前调试中有独立观测，正式结论主要采用5次静态重建的数组。

本轮使用了初次生成后复用的合成资料库。历史调试中出现过索引超时、标签扫描较慢、正文查询超时；随后修复FTS行定位、标签倒排、统计缓存及候选查询路径。保留下来的失败／中断报告见reports/benchmark-attempt-*.json；不把失败样本改写成成功，也不把不同构建的结果混合为一次P95。

## 一、项目背景与问题描述

### 1.1 项目背景

学生、知识工作者和研究人员在学习与工作过程中，需要持续记录课程知识、工作经验、阅读摘要和研究思考。这些内容具有持续积累、频繁修改、跨主题关联和长期保存的特点。

当笔记分散存放于文本文件、办公文档或不同应用中时，用户可能需要反复切换工具、手动整理目录，并依靠记忆查找历史内容。随着资料数量增加，单纯依靠文件名和目录层级进行管理，难以同时满足多维分类、全文检索和知识关联的需要。

Markdown 使用文本标记表达文档结构，适合记录具有标题、列表、代码和引用的内容。本项目拟在 Markdown 编辑基础上，提供标签、全文搜索、双向引用和导出备份能力，形成完整的个人知识管理流程。

### 1.2 现有问题

| 问题 | 具体表现 | 对用户的影响 |
|---|---|---|
| 内容分散 | 笔记存放在多个文件夹或工具中 | 查找成本增加，容易重复记录 |
| 分类方式单一 | 一篇笔记通常只能放入一个目录 | 难以表达同一内容所属的多个主题 |
| 历史内容难以检索 | 用户只能记住部分关键词，无法记住标题或位置 | 已记录知识难以再次使用 |
| 知识关联不足 | 相关笔记之间缺少可访问的连接 | 难以追溯概念来源与相关内容 |
| 保存状态不明确 | 用户无法判断最新修改是否已保存 | 程序异常退出时可能丢失未保存内容 |
| 长期保存能力不足 | 缺少统一导出和可恢复的备份 | 更换设备或数据损坏后难以恢复资料 |

### 1.3 建设必要性

本系统需要将笔记编辑、分类、检索、关联和保存整合到统一工作流程中，减少重复操作，并使用户能够掌握个人数据的存储位置、保存状态和备份方式。

采用本地存储方式，可以使核心功能在无网络环境下使用。通过 Markdown 导出和结构化备份，可以分别满足内容迁移和系统数据恢复需求。

### 1.4 核心问题

本系统重点解决以下问题：

1. 如何统一记录和维护个人 Markdown 笔记。
2. 如何通过标签组织跨课程、跨项目和跨主题的内容。
3. 如何通过标题、正文和标签快速检索历史笔记。
4. 如何建立并维护笔记之间的双向关联。
5. 如何降低保存失败、误删除和本地数据损坏造成的损失。

## 二、项目目标

### 2.1 系统目标

| 编号 | 系统目标 |
|---|---|
| OBJ-01 | 提供笔记创建、编辑、查看、删除、渲染和自动保存能力 |
| OBJ-02 | 提供多标签分类及基于标题、正文、标签的统一检索能力 |
| OBJ-03 | 支持识别双向引用语法，展示当前笔记的引用目标和引用来源 |
| OBJ-04 | 提供 Markdown 导出、完整数据备份及恢复能力 |
| OBJ-05 | 保证核心功能离线可用，并明确保存状态和异常处理方式 |
| OBJ-06 | 为主题和受控插件扩展预留清晰边界 |

### 2.2 用户目标

1. 在统一界面中完成笔记记录和整理。
2. 使用标签对同一篇笔记进行多维分类。
3. 通过记忆中的关键词定位相关内容。
4. 从当前笔记访问相关知识，并查看引用当前笔记的其他内容。
5. 明确判断修改是否已经保存。
6. 将内容导出为可独立读取的 Markdown 文件，并在需要时恢复备份。

### 2.3 预期效果

系统投入使用后，预期形成“记录—分类—检索—关联—备份”的个人知识管理流程。

预期效果通过功能验收、规定规模下的性能测试和用户操作测试验证，不预先声明未经测量的效率提升比例。

## 三、用户分析

下列用户类别用于说明使用差异，不构成不同的系统权限角色。基础版本仅设置一个本地使用者档案。

| 用户群体 | 用户特点 | 使用需求 | 使用习惯 | 主要痛点 |
|---|---|---|---|---|
| 学生 | 笔记按课程和知识点持续积累，Markdown 熟练程度不同 | 记录课堂内容、整理复习资料、关联前后知识点 | 课后补充笔记，考试前集中检索与整理 | 课程内容分散，同一知识点重复记录，复习时难以定位 |
| 知识工作者 | 资料涉及多个项目和主题，内容更新频繁 | 记录工作经验、整理技术资料、跨项目复用知识 | 工作中快速记录，阶段性整理和备份 | 分类容易交叉，历史经验难以查找，重复整理成本较高 |
| 研究人员 | 需要长期积累阅读摘要、术语解释和研究思考 | 关联概念、追溯笔记来源、保存研究记录 | 阅读过程中记录，定期回顾和补充关联 | 笔记之间联系不清晰，难以追踪某个概念在哪些内容中出现 |

**补充用户反馈（SRC-07）：**用户报告已通过微信与4名同学讨论需求，A同学提到曾丢失很多笔记并强调做好备份恢复，用户采纳该建议。此案例支持备份恢复的重要性，不足以推断丢失原因、发生比例或其余3人的意见；具体记录见03文件第6.3节。

### 3.1 共同需求

三类用户共同需要：

- 离线记录和查看笔记。
- 清晰的保存状态和可靠的数据持久化。
- 可组合使用的标签筛选与全文搜索。
- 可解释的引用关系及失效提示。
- 可读取的导出文件与可恢复的备份。

### 3.2 用户能力假设

1. 用户具备基本的文件和文件夹操作能力。
2. 不要求用户预先熟悉 Markdown，系统应提供常用语法帮助。
3. 用户能够选择本地导出位置和备份位置。
4. 基础版本不要求用户注册账号或连接网络。

## 五、功能需求分析

### 5.1 优先级定义

| 优先级 | 定义 | 范围安排 |
|---|---|---|
| P0 | 核心必须实现功能，直接支撑基本使用流程 | 基础版本必须满足 |
| P1 | 重要功能，支撑知识关联、数据迁移和恢复 | 基础版本完整验收时应满足 |
| P2 | 扩展功能，提升个性化和后续扩展能力 | 后续版本实现，不作为基础版本通过条件 |

P0 功能预计在日常使用中高频触发；P1 功能涉及较低频但重要的数据维护和知识关联；P2 功能面向个性化需求。

### 5.2 通用业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 基础版本为单用户、单资料库模式；同一资料库同时只允许一个写入实例 |
| BR-02 | 笔记使用不可变的唯一标识；标题修改不得改变笔记标识 |
| BR-03 | 标题先去除首尾Unicode空白，再做NFC规范化；按规范化后的Unicode码点计数，长度1—100，不得包含换行、控制字符及方括号；唯一性键仅将ASCII的A—Z转为a—z，不做全角半角转换或其他语言的大小写折叠；显示标题保留原英文字母大小写（ASM-02默认口径；确认截止点见A.1） |
| BR-04 | 新建笔记默认标题为“未命名笔记”；发生重名时依次附加数字序号 |
| BR-05 | 标签去首尾Unicode空白、NFC规范化后长度为1—30个Unicode码点；不得包含换行和控制字符；唯一性和显示规则同BR-03 |
| BR-06 | 每篇笔记最多关联20个不同标签；同一标签不得重复关联到同一篇笔记 |
| BR-07 | 删除笔记默认移入回收站；回收站笔记既不作为有效引用来源也不作为目标，不参与普通搜索、重命名联动及引用索引生成；正文保留、不自动永久清除；恢复按当时有效标题重新解析，不保留隐藏的历史引用绑定（ASM-02默认口径；确认截止点见A.1） |
| BR-08 | “已保存”仅表示当前版本的正文、标题、标签关联等业务数据已经持久化，不代表搜索或引用索引已更新；分别显示保存状态和索引状态。业务写入失败保留编辑内容及提交前有效数据；索引失败不撤销已成功的业务提交 |
| BR-09 | 搜索使用NFC规范化及ASCII英文大小写折叠后的字面子串匹配；正文原文不改写，匹配标示须映射回原文；不做全角半角转换、模糊纠错、正则或语义搜索，内部空格按字面匹配 |
| BR-10 | 搜索范围为“全部”时，标题、正文、标签任一匹配即可命中；多个标签筛选采用“同时具备全部所选标签”的规则 |
| BR-11 | 搜索与标签筛选同时使用时，结果必须同时满足两类条件 |
| BR-12 | 引用由有效笔记的已保存正文和当前有效标题集合唯一决定；行内代码、围栏及缩进代码块不参与解析。开始标记前连续反斜杠数为奇数时转义，为偶数（含0）时不转义；具体字符规则见5.6（ASM-02默认口径；确认截止点见A.1） |
| BR-13 | 仅支持单行、非嵌套的 `[[笔记名称]]`；名称内部不得含方括号，按BR-03取得查找键。井号、竖线、反斜杠等合法名称字符一律按字面匹配，不解释为锚点、别名或路径；不合法标记按普通文本处理 |
| BR-14 | 在索引正常可用的常态增量更新中，每个业务事务提交后2秒内发布覆盖该事务的搜索及引用索引；业务提交与索引就绪分别计时。重建或索引故障期间不适用逐次2秒目标，相关查询暂不可用；重建必须覆盖期间已提交的修改和删除，按NFR-P06完成一致版本切换 |
| BR-15 | 正常导出、手动备份和正常恢复前备份先保存编辑内容，再取一致业务快照；保存失败则中止。主数据损坏时按FR-E04故障恢复分支保全原始数据，不要求从损坏库生成有效业务备份。所有业务写入均校验完整最终状态及联动容量，超限或业务提交失败时整体拒绝，不得部分成功；详见6.1.1 |

### 5.3 Markdown 笔记管理（P0）

#### 5.3.1 支持的 Markdown 范围

基础版本应支持以下内容的编辑与渲染：

- 一级至六级标题。
- 普通段落、粗体、斜体。
- 有序列表、无序列表、任务列表。
- 引用块、分隔线。
- 行内代码、围栏代码块。
- 表格和普通超链接。

数学公式渲染、流程图渲染和附件管理不纳入基础版本。图片语法保留原始内容，预览显示占位提示，不自动加载远程图片。原始 HTML 不作为可执行内容渲染。

#### 5.3.2 具体需求

| 需求编号 | 功能描述 | 输入信息 | 处理逻辑 | 输出结果 | 验收标准 | 来源 |
|---|---|---|---|---|---|---|
| FR-N01 | 创建笔记 | 新建操作、可选标题 | 生成标识、校验标题；预计算同名失效引用激活后的最终容量，合格后整体提交 | 新笔记及独立的保存、索引状态 | 标识和有效标题不重复；引用激活超限时整次创建被拒绝，不产生部分记录 | SRC-02、SRC-05；ASM-02、ASM-03 |
| FR-N02 | 编辑笔记 | 笔记标识、标题、Markdown正文 | 校验完整最终状态；标题改变时改写所有有效来源中的匹配标记，包含当前笔记自引用；排除回收站；同一次事务提交标题及受影响正文 | 最新内容、更新时间和保存、索引状态 | 普通修改可重读；联动超限或执行失败时全部业务数据保持原状；提交成功后索引按BR-14更新 | SRC-02、SRC-05；ASM-02、ASM-03 |
| FR-N03 | 删除笔记 | 笔记标识、删除确认 | 提示引用影响；先保存最新内容，再移入回收站；普通列表立即移除，搜索结果失效并按BR-14更新 | 删除结果、回收站记录及索引状态 | 删除后不再允许从旧搜索结果打开该笔记；索引就绪后不含该笔记及其有效引用 | SRC-02、SRC-05；ASM-02、ASM-03 |
| FR-N04 | 查看笔记 | 笔记标识 | 读取有效笔记；展示正文、标签、时间和保存状态 | 笔记详情 | 展示内容与已保存内容一致；不存在或已删除的标识显示明确提示 | SRC-02、SRC-05；ASM-02、ASM-03 |
| FR-N05 | Markdown渲染 | Markdown正文 | 按规定语法解析并安全渲染；不执行脚本和原始HTML | 预览内容 | 支持范围内的语法按预期显示；不支持语法不导致崩溃；恶意内容不执行 | SRC-02、SRC-05；ASM-02、ASM-03 |
| FR-N06 | 自动保存 | 内容变更、计时事件、切换或退出操作 | 停止输入1秒后触发；持续输入至少每5秒触发一次；普通切换或退出前提交最新修改；串行处理版本；重命名按批量联动处理 | 业务保存状态及单独的索引状态 | 普通保存按NFR-P05的2秒目标；切换不必等索引就绪；失败保留编辑内容，不显示“已保存”；批量联动不套用普通保存时限 | SRC-02、SRC-05；ASM-02、ASM-03 |
| FR-N07 | 回收站管理 | 恢复或永久删除操作 | 恢复时校验标题及最终容量，按当前有效标题重建关系；只保留尚存在的标签关联；永久删除需再次确认 | 恢复结果及关联变化说明，或永久删除结果 | 正文按5.6恢复语义处理；已全局删除的标签不复活，同名新标签不自动关联；恢复超限整体拒绝并留在回收站 | SRC-05；ASM-02 |

**自动保存补充规则：**

1. 保存状态至少包括“未保存”“保存中”“已保存”“保存失败”；索引另显示“更新中”“重建中”“可用”“更新失败”。索引未就绪时不将旧搜索或引用结果宣称为当前结果。
2. 在切换笔记时保存失败，应保留当前编辑界面，不静默切换。
3. 在正常退出时保存失败，应提示重试或由用户明确选择放弃未保存修改。
4. 强制结束进程后的恢复按NFR-R01验证；该结果不能证明断电保护。对突然断电，要求不得加载部分事务为有效资料库，无法保证完整性时进入故障恢复；是否承诺断电后最后一次“已保存”数据零丢失，须另行确认并单独测试，当前不作该承诺。
5. 普通保存仅指不改变标题、无需改写其他笔记正文的单笔记正文或标签关联提交。重命名联动、全局标签维护及整体恢复为批量操作，业务提交期间暂停新的业务提交并保留待编辑内容，按NFR-P05—P07单独记录耗时。

### 5.5 全文搜索（P0）

#### 5.5.1 搜索规则

1. 关键词按BR-03去首尾空白和NFC规范化后，不超过100个Unicode码点；内部空格不拆词，匹配键按BR-09生成。
2. 正文搜索针对已保存的 Markdown 源文本，包括代码文本。
3. 空关键词不执行文本匹配，展示符合当前标签筛选条件的有效笔记。
4. 结果按“标题命中、正文命中、仅标签命中”的顺序排列；同一等级按更新时间降序排列，再按笔记标识稳定排序。
5. 一篇笔记同时命中多个字段时，只显示一条结果。
6. 每页最多显示50条结果。
7. 结果摘要不超过120个Unicode码点；正文命中时优先展示匹配位置附近的原文。
8. 一次查询及其分页绑定同一索引版本；任何相关业务提交使当前查询失效，提示“资料已变更”，禁用旧结果翻页，索引就绪后从第一页刷新。无数据变化时保证遍历不重复、不遗漏；变化前后不承诺维持相同页码和总数。点击旧结果须按笔记标识检查当前是否有效；删除项不得打开，修改项显示当前已保存版本。
9. 索引重建或更新失败期间，搜索及引用查询显示不可用原因，不把空结果解释为没有笔记；正常笔记列表和已保存正文仍可查看。分页默认采用上述失效后回到首页策略，降低跨版本快照维护成本；确认截止点见A.1的ASM-02。

### 5.6 双向引用功能（P1）

本系统中，若笔记A正文包含指向笔记B的有效引用，则A的“引用目标”包含B，B的“引用来源／反向链接”包含A。“引用来源”和“反向链接”使用同一组关系数据，避免出现两套不一致的结果。

| 需求编号 | 功能描述 | 输入信息 | 处理逻辑 | 输出结果 | 验收标准 | 来源 |
|---|---|---|---|---|---|---|
| FR-L01 | 自动识别引用 | 已保存正文中的 `[[笔记名称]]` | 按BR-03、BR-12、BR-13及5.6语法规则解析，并查询当前有效标题 | 有效、失效或普通文本标记 | 自引用及特殊字符按规则解析；代码和转义标记不建关系；语法合法但目标不存在时显示失效 | SRC-02、SRC-05；ASM-02 |
| FR-L02 | 建立并维护关联 | 已保存业务快照与数据版本 | 先按最终业务状态校验引用容量，再提交业务；按BR-14更新可重建索引；来源与目标相同的重复引用合并并计数 | 对应业务版本的引用关系及索引状态 | 包含自引用、同名新建激活；增量结果与从同一主数据全量重建的结果一致；超限整笔业务事务拒绝 | SRC-02、SRC-05；ASM-02 |
| FR-L03 | 查看引用目标与跳转 | 当前笔记标识、点击操作 | 索引就绪后展示目标；点击前检查当前标题解析结果及目标有效状态 | 目标列表、索引状态或失效提示 | 正确跳转；目标删除或索引不可用时不使用旧绑定跳转；不自动创建笔记 | SRC-02、SRC-05；ASM-02 |
| FR-L04 | 查看引用来源及反向链接 | 当前笔记标识 | 索引就绪后查询有效来源，展示来源标题、引用次数；包含自引用，排除回收站 | 与当前业务版本一致的反向链接列表 | A引用B时B显示A；自引用有“当前笔记”标识；修改和删除按BR-14反映，重建期间不展示旧结果为当前关系 | SRC-02、SRC-05；ASM-02 |

**引用生命周期规则（ASM-02默认采用名称绑定；确认截止点见A.1）：**

1. 关系完全由当前有效笔记的标题及已保存正文重算，目标标识仅为派生缓存，不代表跨删除、重建保持的历史身份。删除旧笔记后新建同名笔记，所有仍含该名称的有效来源会绑定新笔记；应提示此影响并先校验激活后的关系容量。
2. 有效笔记重命名时，按提交前标题匹配规则，改写所有有效来源中的合法标记，**包括目标自身的自引用**；替换为新显示标题，保留标记外正文。回收站、代码和转义标记不改写。
3. 标题、所有联动正文、版本与时间字段在一次业务事务中提交；先计算最终容量。业务执行中任何一步失败或超限均保持提交前状态；索引失败仅导致索引不可用并重建，不能把已提交的重命名误报为业务回滚。
4. 回收站正文不随其他笔记重命名更新。恢复时按当时有效标题重新解析全部标记，可能失效或指向同名的新笔记，恢复前展示这些变化；若标题冲突而恢复为新标题，正文仍保持原文，不能猜测哪些旧名称曾为自引用。
5. 恢复笔记仅保留仍存在的标签标识；全局已删除的标签及关联不复活，重新创建的同名标签也不自动关联。完整资料库恢复则以备份快照中的标签与关联为准，两种恢复不得混同。
6. 自引用和循环引用合法；自引用计入一条有效关系，同一来源与同一目标的重复标记仅增加出现次数；界面不递归展开关系。

**引用字符规则（ASM-02默认口径；确认截止点见A.1）：**

- 先排除代码区域，再识别未转义、同一行内的非嵌套双括号标记；名称按BR-03规范化查找，正文不整体规范化或重写。
- 开始标记前连续反斜杠奇数个表示转义、偶数个表示未转义；名称内反斜杠按字面处理，不执行转义解码或路径解析。
- 例如，`[[A#B]]`仅查找标题“A#B”，`[[A|B]]`仅查找标题“A|B”，不解释为锚点或别名；斜杠、冒号及反斜杠同样作为合法标题字符。导出文件名与标题分开处理，不能据此访问路径。
- 空名称、跨行、名称内含方括号、嵌套或缺少闭合标记均按普通文本处理，不生成失效关系；连续相邻的两个完整合法标记分别解析。

### 5.7 导出与备份功能（P1）

**导出与备份的区别：**

- **导出：**用于在系统外读取、迁移 Markdown 内容。
- **备份：**用于恢复系统内部的完整业务数据。

| 需求编号 | 功能描述 | 输入信息 | 处理逻辑 | 输出结果 | 验收标准 | 来源 |
|---|---|---|---|---|---|---|
| FR-E01 | 单篇Markdown导出 | 笔记标识、目标路径 | 保存当前内容，按UTF-8原文导出正文；建议文件名需安全化；覆盖同名文件需确认 | 仅含正文的Markdown文件 | 正文、中文、代码及引用标记一致；不附加系统标题、标签、标识或时间元数据；正文原有同名内容不删除 | SRC-02、SRC-05；ASM-04 |
| FR-E02 | 全部笔记批量导出 | 目标路径、导出操作 | 对有效笔记取快照，以唯一标识生成文件名；生成含标识、标题、标签名称、创建及更新时间、文件名的映射清单；打包 | ZIP及元数据清单 | 数量正确、无覆盖；不含回收站、用户设置及备份历史；清单与正文同一快照；不是完整恢复包 | SRC-02、SRC-05；ASM-04 |
| FR-E03 | 数据备份 | 用户选择的外部目录、手动或保护性备份操作 | 生成含业务数据、回收站、标签关联及用户设置的完整快照；记录格式版本与校验；成功后登记本机备份记录 | 完整备份文件及操作记录 | 按本节位置与保留策略执行；失败不登记成功、不损坏既有备份；故障保全的原始文件不冒充有效业务备份 | SRC-02、SRC-05；ASM-04；SRC-07（重要性依据） |
| FR-E04 | 数据恢复 | 备份文件、恢复模式、目标位置及用户确认 | 先验证备份及恢复后的完整容量；正常恢复先生成恢复前备份，故障恢复先原样保全损坏数据；在独立目标构建并校验正文及索引后再切换 | 已验证的新资料库、保全路径及恢复结果 | 正常恢复失败保有原完整资料库；故障恢复失败仍保有原始损坏文件及输入备份，不承诺损坏库可用；不得以无法生成正常备份阻止非破坏性故障恢复 | SRC-02、SRC-05；ASM-04；SRC-07（重要性依据） |

**补充规则：**

1. 单篇导出仅保留正文，不在正文前添加系统元数据；批量导出另用清单保留FR-E02列出的元数据。双向引用均保留原始语法，不保证外部编辑器可跳转。导出包不作为系统完整恢复输入。
2. 备份包含用户档案及可移植设置、有效与回收站笔记、标识、正文、版本与时间、标签及关联；不包含已有备份本体、搜索／引用缓存、插件程序、操作系统凭据或历史绝对路径。恢复时引用按正文重算，本机路径重新选择，不覆盖现有外部备份文件或本机备份历史。
3. 正常备份在完成当前保存后取一致性快照；快照后提交的修改不计入该包。恢复为整体替换，不做合并；从用户确认执行恢复至完成或失败期间停止业务写入，避免快照后修改被替换。
4. **正常恢复：**主数据可读取并通过完整性检查时，须先保存当前修改，创建并校验恢复前备份；失败即中止正常恢复。
5. **故障恢复：**主数据无法读取或完整性检查失败时，停止对其写入，不要求生成有效的恢复前业务备份。优先原位置保留原始文件并在另一目录恢复；需迁移原始文件时，必须先完成可验证的原样隔离保全，禁止边覆盖边尝试恢复。未能保证保全时不得进行任何破坏性覆盖。
6. 两种恢复都先校验输入包版本、结构、字段、关联完整性及最终容量，在独立暂存目标完成业务数据和派生索引验证，再提交活动资料库切换。切换前任何执行失败均不得改变原活动库或故障原始文件，也不得修改输入备份。空间不足时中止并提示选择其他位置，不清除原数据腾挪空间。
7. 切换提交后才报告成功；切换期间故障或结果回执丢失时，重启后先核实最终状态，只允许使用完整且已验证的旧库或新库，不得混用。未能判定时保持停止写入，展示保全位置及重试入口。正常恢复失败保留原完整库；故障恢复失败只保证原始材料未被覆盖，不声称其已可正常使用。

**备份、保留与迁移策略（ASM-04默认口径；确认截止点见A.1）：**

- 基础版本采用用户手动触发的全量备份，并在正常恢复、数据格式升级前触发保护性全量备份；不增加定时、增量或云备份。
- 用户选择本地磁盘或可移动磁盘上位于活动资料库目录之外的可写目录。不得把备份目录放入待打包范围；每次生成独立时间及标识命名的文件，不自动覆盖旧备份。
- 成功备份和故障隔离材料不自动轮换或删除，由用户在核实有效后手动管理；界面显示路径、时间、大小和状态。不保证无限保留，外部删除、磁盘损坏和空间不足均可能使文件不可用。
- 用户负责备份频率、保留数量、独立介质副本及妥善保管。系统负责真实报告结果及校验恢复，不把“同盘备份成功”解释为抵御磁盘损坏。
- 默认支持在相同支持环境、兼容格式版本间，手动复制完整备份后执行整体恢复进行跨设备迁移；该过程不含网络传输、自动同步或两端合并，原设备数据不自动删除。
- 默认基础版本不支持一次性Markdown文件／目录导入，外部文本可粘贴到新笔记。FR-E04仅接收本系统兼容完整备份，不接收单篇或批量导出包；改变此默认范围须在A.1截止点前记录变更，不因“待确认”产生两个并行实现方案。


**完整备份包格式及校验（ASM-04默认口径）：**

- 扩展名为 `.zip`，根目录恰有 `manifest.json` 与 `data.json` 两个UTF-8 JSON文件；不加密，不嵌入其他归档、可执行文件、索引或历史备份。
- manifest记录format_version（当前为整数1）、backup_id、snapshot_at、note_count（含回收站）、data_size_bytes、checksum_algorithm（固定为SHA-256）及data_sha256（64位小写十六进制）。data.json记录第7章规定的用户可移植设置、笔记、标签和笔记标签关联；不保存派生引用缓存及本机备份历史。
- data_sha256针对包内data.json的**原始UTF-8字节**计算，校验前不得重新序列化或改换行；manifest自身不纳入该摘要，以避免自包含校验。7.7的checksum则为归档完成后整个ZIP的SHA-256，保存在包外的本机备份记录中。
- 恢复先检查文件清单、重复条目、越界路径及版本，再核对长度和摘要，并独立校验字段、标识唯一性、标签外键、全部容量和重算引用数；摘要相同不代表业务结构有效。未知版本、额外文件、缺失文件、损坏JSON或任一不一致均整包拒绝；仍遵守正常／故障恢复的原数据保护规则。
- SHA-256用于发现损坏，不证明来源可信，也不提供加密或防篡改认证；基础版本不增加数字签名服务。

## 六、非功能需求分析

### 6.1 性能需求

#### 6.1.1 基准环境与数据规模

以下条件作为性能验收基线：

- 操作系统：Windows 10或Windows 11，64位。
- 硬件：4核处理器、8 GB内存、固态硬盘。
- 数据位置：本地磁盘目录，不使用网络共享目录。
- 笔记总数：不超过10,000篇，包含回收站笔记。
- 单篇正文：UTF-8编码后不超过1 MiB。
- 全部正文总量：不超过300 MiB。
- 标签总数：不超过2,000个。
- 有效引用关系：不超过100,000条。
- 单用户操作，无多个写入实例并发修改。

容量针对**整次操作的最终业务状态**校验，而非只校验当前编辑文本。正文总量包含回收站，按UTF-8字节计量；有效引用数量为有效来源与有效目标的不同有向标识对数量，自引用计一条、重复出现不重复计数。失效引用暂不计入有效关系上限，但其被激活时必须重新校验。

校验覆盖新建、普通编辑、重命名及全部正文联动、回收站恢复、同名目标出现导致的引用激活、完整备份恢复。须检查每篇正文、全部正文、笔记、标签、单篇标签数及重算后的有效关系总数；超限时整个操作被拒绝，标题、正文、标签关联、删除状态和版本均不部分改变，不截断内容或只激活部分引用。重建期间也必须基于权威业务数据校验，不能以过期索引判断容量。

重命名及恢复提交前应串行化业务变更，保证校验结果对应最终提交状态。拒绝业务提交不清空用户输入；索引更新失败不属于容量拒绝，按BR-08、BR-14处理。若打开的旧资料库已超限，只允许查看、导出及不增加任何超限指标的删除清理；其他写入拒绝，不能通过部分写入“修复”。

上述容量值作为ASM-03的默认验收上限，确认截止点见A.1；它们仍是规划目标，并非实测能力。

## 七、数据需求分析

### 7.1 通用数据规则

1. 各实体使用全局唯一且不可变的标识。
2. 文本采用Unicode字符，导出与交换使用UTF-8编码。
3. 时间字段采用包含时区信息的统一时间格式，界面按本地时区显示。
4. 空值与空字符串应区分，必填字段不得为空。
5. 搜索索引和引用索引属于可重建的派生数据；其标识可以在重建后变化，正文、笔记标识和标签关联才是权威业务数据。引用始终按当前有效标题重新解析，不使用缓存保留历史身份。
6. 业务数据的新增、修改、删除及联动须按完整最终状态校验和提交；资料库须能区分已提交业务版本与已发布索引版本。重建基于一致快照并补齐之后的已提交变更，切换时两者一致；用于恢复的版本信息须足以防止旧索引覆盖较新数据。
7. 名称的规范化、长度及比较以BR-03、BR-05为准；正文原文不因搜索规范化改变。备份校验从业务内容重新计算引用数量，不信任归档中缓存的引用数量。

| created_at | 时间，必填 | 记录档案创建时间 |

| updated_at | 时间，必填 | 排序及展示更新时间 |
| deleted_at | 可空时间 | 非空表示处于回收站 |

有效笔记标题按BR-03的比较键唯一；回收站可保留同名历史内容，恢复前需消除标题冲突并校验最终容量。恢复改名不推测或改写正文中的历史自引用，按5.6重新解析；有效笔记重命名则须改写自身和其他有效来源的匹配标记。

### 7.4 标签实体

| 字段 | 类型与约束 | 用途 |
|---|---|---|
| tag_id | 唯一标识，必填 | 稳定标识标签 |
| user_id | 用户标识，必填 | 标识所属使用者 |
| name | 文本，符合BR-05 | 展示、搜索和分类 |
| created_at | 时间，必填 | 记录创建时间 |
| updated_at | 时间，必填 | 记录名称修改时间 |

### 7.5 笔记与标签关联实体

| 字段 | 类型与约束 | 用途 |
|---|---|---|
| note_id | 笔记标识，必填 | 关联笔记 |
| tag_id | 标签标识，必填 | 关联标签 |
| created_at | 时间，必填 | 记录关联时间 |

同一组`note_id`与`tag_id`不得重复。笔记与标签为多对多关系。全局删除标签清除包括回收站在内的全部关联；回收站恢复不复活这些关联，同名新标签也不自动关联。完整备份恢复按快照还原合法关联，不等同于回收站恢复。

### 7.6 笔记引用关系实体

| 字段 | 类型与约束 | 用途 |
|---|---|---|
| reference_id | 派生记录标识，必填 | 标识当前索引中的记录，重建后不保证保持 |
| source_note_id | 笔记标识，必填 | 标识引用来源 |
| target_note_id | 可空笔记标识，派生 | 当前标题匹配到的有效目标；不是跨删除或重建的历史绑定 |
| target_title_text | 文本，必填 | 保存引用名称，支持失效提示与重新解析 |
| occurrence_count | 正整数 | 记录来源正文中的出现次数 |
| status | 有效／失效 | 表示解析状态 |
| updated_at | 时间，必填 | 记录最近解析时间 |

同一来源笔记对同一有效目标的多次引用应合并为一条关系；失效引用按规范化后的目标名称合并。

引用位置及目标均由当前业务快照重新解析；回收站笔记不产生关系记录。重建可改变reference_id和解析时间，但同一快照下的来源、目标、状态及出现次数必须一致。失效名称出现同名有效目标时按名称重新绑定，容量校验不能因索引尚未刷新而省略。

### 7.7 备份记录实体

| 字段 | 类型与约束 | 用途 |
|---|---|---|
| backup_id | 唯一标识，必填 | 标识一次备份操作 |
| user_id | 用户标识，必填 | 标识备份归属 |
| backup_type | 手动／正常恢复前／升级前 | 说明有效业务备份的产生原因，故障原始保全不计为成功业务备份 |
| file_path | 本机绝对路径 | 定位备份文件，不随业务备份迁移；历史成功记录不保证文件仍存在 |
| format_version | 版本标识 | 检查恢复兼容性 |
| snapshot_at | 时间 | 记录数据快照时间 |
| completed_at | 可空时间 | 记录完成时间 |
| note_count | 非负整数 | 记录快照中的笔记数量 |
| file_size | 非负整数，字节 | 展示备份大小 |
| checksum | SHA-256，小写64位十六进制 | 完整ZIP的包外摘要；包内data.json摘要另存manifest，见5.7 |
| status | 进行中／成功／失败 | 反映真实操作状态 |
| error_summary | 可空文本 | 保存不包含正文的失败原因 |

故障恢复产生的原始数据隔离目录、原始文件校验值和恢复输入路径属于故障处理记录，不计入`status=成功`的业务备份，也不能被当作可恢复资料库。系统至少应向用户显示其保全位置、保全是否完成、输入备份位置及恢复结果；若无法安全记录这些信息，不得执行破坏性覆盖。

### 7.8 数据关系及生命周期

- 一个用户拥有多篇笔记、多个标签和多条备份记录。
- 笔记与标签通过关联实体形成多对多关系。
- 笔记之间通过有向引用形成多对多关系。
- 删除标签清理全部关联（含回收站），不删除笔记；重新创建同名标签不恢复旧关联。
- 软删除保留正文及当时标签关联，但退出有效搜索与引用；全局标签删除仍会清理其关联，其他笔记重命名不改写其正文。
- 永久删除清理其记录；其他正文中的引用文字保留，按当前有效标题重新解析；之后同名新建可重新绑定，不保留历史目标身份。
- 恢复备份后，以完整业务快照重建搜索和引用；故障原始材料及恢复前保护副本不被业务替换清理。
- 历史备份记录留在本机，不包含在跨设备业务快照中；恢复操作保留现有外部备份及记录，并记录本次输入来源与结果。

## 八、系统边界与约束

### 8.1 系统包含范围

基础版本包含：

1. Markdown笔记管理、渲染和自动保存。
2. 标签管理与组合筛选。
3. 标题、正文和标签搜索。
4. 双向引用识别、维护和访问。
5. 回收站、导出、备份和整体恢复。
6. 本地用户设置及必要的状态、异常提示。

### 8.2 系统不包含范围

基础版本不包含：

- 多人实时协作。
- 云同步及跨设备自动合并。
- 社交分享和内容发布。
- 在线账号体系和组织权限管理。
- 移动端应用。
- PDF、图片、音视频附件管理与OCR检索。
- AI生成、语义搜索或自动知识分类。
- 通用Markdown文件夹持续监听与外部编辑器双向同步。
- 完整历史版本管理。
- 插件商店、知识图谱可视化。
- 数学公式和流程图渲染。

其中插件、主题及受控功能扩展保持P2。云同步、移动端及协作会引入账号、跨设备冲突、平台适配和并发一致性成本，基础版本排除这些内容；P2扩展需要额外的接口兼容与隔离验证，因此后置，以优先保证个人离线记录和数据恢复。

ASM-04默认跨设备迁移仅复用完整备份的手动复制与整体恢复，一次性Markdown导入不纳入基础版本；确认截止点见A.1。导出能力不意味着支持导入或跨端同步。其余范围外事项须经需求变更后方可纳入。

### 8.3 技术约束

1. 核心功能必须在断网条件下运行。
2. 数据保存在用户具有写入权限的本地目录。
3. 不限定具体编程语言、框架或数据库，但实现方案必须满足一致性、性能和安全要求。
4. 同一资料库不得被多个程序实例同时写入；第二个实例应转向已有实例或拒绝写入。
5. 外部程序直接修改系统内部数据文件不属于受支持的操作方式。

### 8.4 资源约束

1. 项目按个人课程项目规模规划，优先完成P0与P1。
2. 不依赖付费云服务、持续在线服务器或专业运维人员。
3. P2不得挤占数据保存、搜索正确性、引用一致性及备份恢复的验证工作。
4. 用户规模、性能指标及支持语法范围应在开发前由项目负责人确认。

### 8.5 环境与接口约束

| 接口或依赖 | 约束 |
|---|---|
| 本地文件系统 | 应处理空间不足、目录不可写、文件占用和非法文件名 |
| Markdown导出 | 使用UTF-8；单篇为Markdown文件，批量为ZIP及映射清单 |
| 备份接口 | ZIP内含manifest.json和data.json，format_version=1；原始字节SHA-256校验，具体字段与拒绝规则见5.7 |
| 操作系统浏览器 | 仅在用户点击允许的外部链接后调用 |
| 网络 | 基础版本不依赖网络，不主动请求远程笔记内容 |
| 数据恢复 | 正常／故障分支按5.7执行；仅接受已声明兼容的完整备份，拒绝未知版本和最终状态超限；不接收Markdown导出包；迁移及导入按ASM-04默认范围，截止点见A.1 |

## 九、验收标准

### 9.1 验收原则

1. 基础版本验收覆盖全部P0、P1需求及适用的非功能需求。
2. P2作为后续版本单独验收。
3. 功能验收同时覆盖正常流程、边界输入和主要异常流程。
4. 性能测试必须记录软硬件环境、数据规模、测试次数和实际结果。
5. 本节列出测试方法与预期结果，不表示测试已经执行。

### 9.2 功能验收用例

#### 编号：AC-01

**对应功能：**FR-N01、FR-N02，笔记创建与编辑。

**验收条件：**标题和标识符合规则；正文修改可持久化；非法标题不会生效。

**测试方法：**连续创建两篇默认笔记，检查标题和标识不同；将其中一篇命名为“课程笔记”，另一篇尝试使用相同标题，确认被拒绝；输入包含中文、英文和代码的正文，保存并重启，逐字比较内容。

#### 编号：AC-02

**对应功能：**FR-N04、FR-N05，查看与渲染。

**验收条件：**支持的Markdown语法正确显示，不支持的内容不导致崩溃。

**测试方法：**建立包含各级标题、列表、任务列表、引用、代码块、表格和链接的固定样例；逐项核对显示结果；输入不完整标记及原始HTML，确认系统仍可编辑且不执行HTML脚本。

#### 编号：AC-03

**对应功能：**FR-N06，自动保存。

**验收条件：**停止输入1秒后发起保存，单次持久化不超过2秒；持续输入期间至少每5秒发起一次保存。

**测试方法：**分别执行一次修改后停止输入，以及连续输入15秒；记录业务保存触发及完成时间，再单独记录索引就绪时间；切换笔记再返回，确认正文已持久化且保存状态正确；在索引延迟时确认界面不会把“已保存”误报为“索引可用”。

#### 编号：AC-04

**对应功能：**FR-N03、FR-N07，删除与回收站。

**验收条件：**软删除可恢复，永久删除需确认，恢复时处理标题冲突。

**测试方法：**删除带标签的笔记，确认普通列表和搜索中不可见；恢复后核对正文及仍存在的标签，先全局删除其中一个标签再恢复，确认该标签不复活；再次删除并新建同名笔记，确认恢复时要求改名；取消永久删除，确认内容仍在回收站。

#### 编号：AC-05

**对应功能：**FR-T01—FR-T04，标签维护与关联。

**验收条件：**标签唯一、关联不重复，删除标签不删除笔记。

**测试方法：**创建“课程”“复习”两个标签并关联到同一篇笔记；重复关联同一标签，确认无重复记录；重命名“复习”为“期末复习”，确认关联保持；删除“课程”，确认笔记仍在；尝试添加第21个标签，确认被拒绝。

#### 编号：AC-06

**对应功能：**FR-T05、BR-10、BR-11，组合筛选。

**验收条件：**多个标签采用交集规则，与文本搜索叠加时同时满足两类条件。

**测试方法：**准备笔记A同时具有“课程”“复习”，B仅有“课程”，C仅有“复习”；同时选择两个标签，确认仅显示A；输入仅B正文包含的关键词，确认结果为空；清空条件，确认三篇笔记均重新可见。

#### 编号：AC-07

**对应功能：**FR-S01—FR-S03，搜索匹配。

**验收条件：**标题、正文和标签搜索范围正确，全部搜索合并且去重。

**测试方法：**准备三篇笔记，分别仅在标题、正文、标签中包含“离散数学”；按三个范围查询，各返回对应的一篇；选择全部范围，返回三篇；使其中一篇同时在多个字段命中，确认仍只出现一次。

#### 编号：AC-08

**对应功能：**FR-S04，搜索展示与分页。

**验收条件：**结果排序、总数、摘要、分页和零结果提示符合规定；分页绑定索引版本，数据变化后旧查询失效并重新从第一页开始。

**测试方法：**准备120篇命中笔记及固定更新时间；确认每页最多50条，遍历三页后共有120个不同标识；在翻页前修改或删除一篇，确认旧查询失效、提示刷新且不能跨版本翻页；索引就绪后从第一页重新查询；核对字段命中优先级及时间排序；查询不存在的关键词，确认显示无结果提示而非索引不可用提示。

#### 编号：AC-09

**对应功能：**FR-L01—FR-L04，引用识别与双向查询。

**验收条件：**仅合法正文引用建立关系，引用目标和来源一致。

**测试方法：**在A的普通正文中两次输入 `[[B]]`，在代码块中再输入一次，并在A中加入一次 `[[A]]`；保存并等待索引就绪，确认A到B只有一条关系、出现次数为2，B的反向链接中只有一个A条目，A显示“当前笔记”自引用；删除普通正文中的两处引用，确认A到B关系消失而自引用按正文变化处理；重建索引后逐项比较结果。

#### 编号：AC-10

**对应功能：**FR-N02、FR-L02，引用生命周期。

**验收条件：**重命名保持关联且包含自引用；删除进入回收站后不参与联动；同名新建按当前正文重新绑定；恢复时重新解析而不使用旧索引绑定。

**测试方法：**建立A引用B，并在B中加入 `[[B]]`；将B重命名为C，确认A及B自身的合法引用均变为 `[[C]]`，代码块和转义内容不变；模拟联动执行中失败，确认标题、正文和版本全部保持原状；将C移入回收站，确认其不参与后续重命名；新建同名C，确认有效来源按名称重新绑定且先执行容量校验；恢复旧C时确认按最终标题重新解析，不恢复隐藏历史绑定。

#### 编号：AC-11

**对应功能：**FR-E01、FR-E02，导出。

**验收条件：**单篇正文一致，批量数量正确，文件无冲突，中文编码正常。

**测试方法：**导出包含中文、代码和双向引用的笔记，用独立文本编辑器打开核对；批量导出含有效笔记与回收站笔记的资料库，解压后核对有效笔记数量和映射清单；对已有文件取消覆盖，确认原文件不变。

#### 编号：AC-12

**对应功能：**FR-E03、FR-E04，备份与恢复。

**验收条件：**正常恢复后的业务数据与备份快照一致，并具有恢复前备份；故障恢复不以生成恢复前备份为前提，原始损坏材料得到保留或隔离。

**测试方法：**准备包含有效笔记、回收站、标签和引用的数据集并备份；修改及删除部分数据后执行正常恢复，确认先生成并校验恢复前备份，再比较恢复结果与原快照；另复制一份主数据并模拟不可读或校验失败，进入故障恢复，确认原文件不被覆盖，在独立目标恢复合法备份；模拟暂存构建、容量校验或切换执行失败，确认原活动库、原始损坏文件和输入备份均保留且不生成空库。

#### 编号：AC-13

**对应功能：**FR-E03、FR-E04，备份异常处理。

**验收条件：**损坏、超限及不兼容备份不能覆盖现有数据；正常恢复备份失败时原完整库保持可用，故障恢复失败时原始材料保持可取。

**测试方法：**分别使用截断文件、校验不一致文件、不支持版本文件和超过容量限制的测试备份；逐个尝试正常恢复；确认操作被拒绝且原资料库内容、数量及可读性不变；再对不可读主数据执行故障恢复，确认不因无法生成恢复前备份而阻止非破坏性恢复，且原始材料和输入备份仍存在。

### 9.3 非功能及边界验收用例

#### 编号：AC-14

**对应功能：**NFR-P01—NFR-P07，性能。

**验收条件：**按6.1环境、规模及ASM-03默认阈值分别判定；人工冻结前的测试结果注明“默认方案”，不宣称正式验收。失败、超时和索引不可用的操作单独报告，不从样本中无声删除。

**测试方法：**构建符合容量上限的测试资料库，预先准备覆盖标题、正文、标签及无结果情况的查询集合；每类常态搜索执行100次，仅在索引可用时从实际查询提交至首屏可操作计时，按耗时升序取第95个值作为P95；普通保存单独测量从保存触发至业务事务持久化，重命名联动、标签批量变更、恢复和索引重建分别记录总耗时，不混入普通保存或常态搜索样本；明确报告硬件、数据量、索引状态和是否发生重建。每种普通保存、笔记打开至少100次，报告P95及最大值；没有P95限定的时限按每次最大值检查。启动、重命名、全局标签操作、恢复及静态重建各执行5次，均满足5秒／30秒／30秒／180秒／60秒上限；恢复分别覆盖正常与故障分支，确认按钮点击之前的人工选择时间不计入。

动态重建另执行5次：使用满足6.1容量且留有编辑余量的10,000篇测试笔记，在快照读取完但尚未发布阶段的测试控制点依次提交20次操作（10次正文编辑、5次删除、5次标签修改），相邻提交完成间隔至少1秒，全部提交在开始后60秒内完成，之后停止写入。测量开始至完整发布不超过120秒、最终暂停不超过5秒，并逐项对照这20次提交的最终正文、删除状态及标签。需要测试控制点才能重复的情况应在记录中说明；控制点等待时间单列，不用于隐藏真实计算耗时。

#### 编号：AC-15

**对应功能：**NFR-R01—NFR-R04，保存与故障恢复。

**验收条件：**已保存数据不丢失；写入失败不破坏旧数据；索引可重建；强制结束与断电验证分别报告。

**测试方法：**在显示“已保存”后强制结束进程并重启，核对最后完整业务版本；单独模拟断电或等价的突然中断，确认不能加载部分事务，必要时进入故障恢复，不把强制结束结果当作断电结论；模拟目录不可写或磁盘空间不足，确认显示失败且编辑内容保留；破坏测试用索引文件，启动重建，在重建期间编辑、删除和修改标签，确认这些已提交变化全部纳入新索引，切换前不发布半成品。

#### 编号：AC-16

**对应功能：**NFR-S01—NFR-S05，安全及非法操作。

**验收条件：**危险内容不执行，文件操作不越界，取消危险操作后数据不变。

**测试方法：**输入脚本片段和危险协议链接，确认不执行；使用包含越界路径的测试备份，确认拒绝；分别取消永久删除、文件覆盖和整体恢复，核对原始数据未改变。

#### 编号：AC-17

**对应功能：**NFR-U01—NFR-U07，易用性。

**验收条件：**核心功能可发现、可通过键盘操作，目标用户能够完成规定任务。

**测试方法：**核对新建操作次数、快捷键、焦点显示和错误提示；组织5名目标用户按统一说明完成新建、标签、搜索和导出任务，记录完成情况、时间与需要帮助的位置。

#### 编号：AC-18

**对应功能：**BR-01、容量约束及离线使用。

**验收条件：**核心功能离线可用；第二实例不得并发写入；超限不破坏现有数据。

**测试方法：**断网后完成新建、搜索、引用和备份；尝试用第二实例打开同一资料库，确认不能同时写入；分别在普通编辑、重命名（含联动）、同名目标激活、回收站恢复和完整备份恢复时构造正文、笔记、标签及引用关系超限，确认每次整笔拒绝、原状态和编辑输入保留，不出现部分激活或部分联动。

#### 编号：AC-19

**对应功能：**NFR-M01—NFR-M05，可维护性。

**验收条件：**具备模块职责、数据版本、恢复及需求追踪说明。

**测试方法：**评审模块与接口文档，核对各需求编号对应的测试记录；验证未知格式版本被安全拒绝；在测试资料库中执行索引重建与数据升级失败恢复流程。

#### 编号：AC-20

**对应功能：**FR-X01—FR-X03，P2扩展能力。

**验收条件：**插件和主题能够受控启停，异常可回退且不损坏核心数据。

**测试方法：**在P2实施后，分别加载合法、不兼容及运行失败的测试插件和主题；检查权限确认、错误隔离、默认主题回退及卸载结果；确认笔记内容保持不变。

#### 编号：AC-21

**对应功能：**BR-03、BR-05、BR-12、BR-13、FR-L01，规范化及特殊字符解析。

**验收条件：**名称规范化、长度、英文大小写、转义和特殊字符规则一致，正文显示不被规范化改写。

**测试方法：**使用前后空白、NFC等价字符、ASCII英文大小写、全角字符、组合字符、井号、竖线、斜杠、冒号和反斜杠标题；分别测试 `[[A#B]]`、`[[A|B]]`、奇数和偶数个前置反斜杠、代码块、跨行、嵌套、空名称及缺少闭合标记；核对唯一性、有效／失效／普通文本状态及自引用结果。

#### 编号：AC-22

**对应功能：**FR-N02、FR-N07、FR-T03、FR-L02、NFR-P06，索引重建和全局标签生命周期。

**验收条件：**重建与全量解析语义一致；重建期间编辑、删除和标签操作不丢失；全局删除标签后恢复不复活关联。

**测试方法：**破坏索引并启动重建；在重建期间提交正文编辑、删除笔记、修改标签和新建同名目标，记录业务版本；重建完成后按权威业务数据全量解析，对比来源、目标、状态、出现次数、搜索结果和分页；全局删除一个标签后将带该标签笔记移入回收站并恢复，确认标签不复活；新建同名标签确认不自动关联。

#### 编号：AC-23

**对应功能：**FR-N02、FR-L02、FR-N07，批量联动执行失败保护。

**验收条件：**业务提交前失败或超限时整体拒绝，不能留下部分业务状态；提交后增量索引失败保留已提交数据并显示索引不可用；完整恢复在暂存索引校验成功后才切换，不把两种失败混为一谈。

**测试方法：**分别在重命名、引用激活提交前注入业务写入失败，检查全部业务字段保持旧状态；在提交成功后注入增量索引失败，检查新正文仍在且可重建索引。对完整恢复，在暂存索引构建、校验及切换阶段分别注入失败，按FR-E04验证原库或原始损坏材料、输入备份均保留；切换回执不明时只接受可核实的完整旧／新状态，不将其误称为已回滚。

#### 编号：AC-24

**对应功能：**NFR-R05、FR-E03、FR-E04，备份可恢复。

**验收条件：**恢复后业务字段与同一备份快照一致，派生引用语义一致；本机路径和备份历史不得被外来包覆盖。

**测试方法：**准备有效笔记A、带标签笔记B、回收站笔记C及A→B引用，记录所有ID、正文、版本、时间、删除状态、设置与标签关联并备份；备份后修改A并删除标签，再正常恢复，逐字段对照原快照（而非修改后的数据），检查回收站、反向链接、搜索及本机备份历史。修改data.json一个字节而不更新摘要，确认整包拒绝；更新摘要但留下错误标签外键，仍应拒绝。记录实际差异及包版本，未执行前不得填“通过”。

#### 编号：AC-25

**对应功能：**NFR-R06、FR-E04，启动损坏与故障恢复。

**验收条件：**启动检测主数据损坏后不自动生成空库覆盖，不写损坏材料；合法备份可在独立目标恢复；无合法备份时保持安全停止写入。

**测试方法：**复制测试资料库，记录原始文件清单与可读取字节的SHA-256，截断测试主文件使其校验失败后启动；检查故障入口和原文件未被改写。分别选择合法备份、损坏备份和无备份，检查成功切换／明确拒绝及原文件、输入包保留。再在暂存构建及切换前注入写入失败；不可读取文件的保全以原位置未覆盖及错误记录为证，不伪造其摘要。

#### 编号：AC-26

**对应功能：**NFR-R07、NFR-M02，版本变更保护。

**验收条件：**任何数据格式升级先完成有效保护备份；保护备份失败不得开始升级；升级失败保持或恢复升级前完整数据。

**测试方法：**在实现版本迁移时准备该实现明确支持的旧版本测试库及已知字段清单（记录真实旧／新版本号）；先令备份目录不可写，确认主数据字节及版本不变；再允许备份并在迁移中途注入失败，核对旧版本、正文、标签和回收站可用及备份完整；成功分支核对升级后字段保留。若没有可运行的迁移实现，只能标“未执行”，不可用拒绝未知版本代替本用例；基础版本冻结时须明确所支持的迁移路径。

#### 编号：AC-27

**对应功能：**NFR-S06，日志最小化。

**验收条件：**常规、错误、崩溃和调试日志均不得泄露正文、标题、标签、查询词、备份内容或凭据；必要操作类型、时间、结果码仍可排障。

**测试方法：**在各敏感字段写入不同唯一标记，执行编辑、搜索、导出、备份、恢复及故意触发的失败；收集产品生成的全部日志（包括崩溃报告和调试输出），搜索原始标记及常见转义／编码形式，并抽查错误堆栈。任一敏感内容出现即不通过；测试用例自身保存的受控测试材料不计为产品日志。

#### 编号：AC-28

**对应功能：**NFR-S07、FR-X01、FR-X03，插件权限控制（P2）。

**验收条件：**未授权插件不能读写任意文件、修改笔记或访问网络；用户拒绝／撤销授权立即生效，核心编辑与数据保持可用。

**测试方法：**仅在P2实现后运行测试插件：先不授予权限，分别尝试读取资料库外测试文件、修改测试笔记和连接本地模拟网络端点，均应拒绝且无副作用；只授予一个编辑命令能力，确认不能连带获得文件／网络能力；停用后再尝试访问应失败。记录授权界面、文件前后摘要及端点访问记录；基础版本无插件机制时标“P2未执行”，不得写为已通过。
